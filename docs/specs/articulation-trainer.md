# Articulation & EQ Trainer — Technical Spec (v2, self-adaptive)

**Author:** Lior (strategist) · **Date:** 26.7.2026 · v2: same day — zero-authoring adaptive engine
**Executor:** Eitan-Dev (`waoengineer`) · **Scripts/personas Hebrew:** Tamar/Noa (`waocopy`)
**Status:** SPEC — not yet implemented

## 1. What & why

A private, staff-only training app inside the WAO Next.js site where Eitan practices
**spoken articulation, persuasion, and emotional intelligence** against AI role-play
partners — in **Hebrew, by voice**, so it feels like a real conversation.

**North-star purpose:** Eitan sells WAO services to Israeli SMB owners. Every scenario
ultimately trains a WAO-relevant conversation: discovery calls, objection handling,
pricing talks, difficult clients, referral asks. This is not a generic charisma course —
it's a sales-conversation gym with an EQ curriculum wrapped around it.

Inspired by the RISE "Unlock Your Charisma" curriculum (14 lessons) but upgraded:
deliberate practice with a live partner + measurable feedback, not passive video lessons.

**v2 principle — zero manual authoring.** Eitan never writes personas, scripts, or
scenarios. Everything is generated by a **Coach agent** (Claude) from three inputs:
the WAO context the repo already holds, a one-time *training charter*, and the growing
body of session analysis. The system adapts itself: every debrief updates a skill
profile; the next session is generated to attack the current weakest skill.

**Tracks** (charter-weighted, default 70/20/10):
- **T1 · WAO funnel selling** — every scenario ends in moving an Israeli SMB owner
  toward the WAO AI funnel (discovery, objections, pricing, close, referral).
- **T2 · Professional networking** — events, LinkedIn-to-call, partner intros, pitch-in-60s.
- **T3 · Social/general** — friends, small talk, conflict, listening. Skills transfer
  both ways; T3 keeps the EQ base broad.

## 2. Core loop (one session)

1. Pick a **scenario** (or the app suggests the next one from the weekly plan).
2. App starts a voice agent configured as the scenario's **persona** (Hebrew voice,
   personality prompt, hidden objectives).
3. Eitan talks. The agent role-plays — pushes back, gets emotional, stalls, objects —
   per the scenario's difficulty **level**.
4. Session ends (goal reached, time cap, or manual stop). Full transcript is captured.
5. **Debrief:** a Claude judge scores the transcript against the scenario's rubric
   (clarity, empathy, listening ratio, objection handling, filler words, outcome) and
   returns 2–3 concrete drills. Score is stored; progress unlocks the next level.

## 3. Voice engine — options & cost (web-verified 26.7.2026)

Assume ~300 practice minutes/month (5 sessions/week × ~15 min).

| Route | How | Cost @300 min/mo | Hebrew quality | Build effort |
|---|---|---|---|---|
| **A. ElevenLabs Agents** (conversational AI) | One managed agent, per-session prompt/voice overrides, WebRTC SDK | ~$0.08–0.12/min → **~$24–36/mo** (Creator $22 incl. ~275 min) | **Proven good (v3-era voices)** | Lowest — turnkey turn-taking, barge-in, transcripts |
| **B. Gemini Live API** (native speech-to-speech) | WebSocket session, system prompt = persona | ~$0.005 in + $0.018 out /min → **~$5–8/mo** | Unverified for Hebrew role-play — must bake-off | Medium — we manage session, transcript capture |
| **C. DIY cascade: browser STT → Claude → ElevenLabs v3 TTS** | Reuse existing bot infra; TTS ≈ 1 credit/char (v3), agent speaks ~100k chars/mo | TTS ~$22 (Creator credits) + LLM ~$3–5 → **~$25–30/mo** | Good (same v3 voices) | Highest — latency/turn-taking is on us; feels least "real" |
| **D. DIY with Google Cloud TTS (Chirp 3 HD)** | Same as C, TTS at $30/1M chars (1M/mo free tier) | **~$5/mo** (TTS effectively free) | **Blocker: Hebrew not supported / not credible in Chirp 3 HD or Gemini TTS as of mid-2026** | Highest |

**Read:** Google Cloud TTS is the cheap route on paper but Hebrew support is the
blocker — reports through 2025–26 say Hebrew is absent from Gemini TTS's supported
languages and weak/absent in Cloud TTS. **Gemini Live** is the real cheap contender
(~4× cheaper than ElevenLabs Agents) *if* its Hebrew speech quality holds up in
free-flowing role-play.

**Decision (bake-off resolved 26.7.2026): Route B — Gemini Live — is the engine.**
- Probe result: `gemini-2.5-flash-native-audio` **rejects** `he-IL`; but
  **`gemini-3.1-flash-live-preview`** passed on all three axes — perfect Hebrew ASR,
  in-persona native spoken register («נו, מה עכשיו?… תכל׳ס»), and voice quality
  approved by Eitan by ear ("Sabra all the way"). Default model:
  `gemini-3.1-flash-live-preview` (override via `GEMINI_LIVE_MODEL`).
- ElevenLabs Agents demoted to fallback; the M1 ElevenLabs path stays in the codebase
  behind the engine abstraction but is not the default (its API key scope fix is
  optional now).
- Route D stays dead until Google ships credible Hebrew TTS voices; re-check quarterly.

The engine sits behind one server interface (`startSession`, `endSession`,
`getTranscript`) so swapping providers never touches UI or scenario data.

## 3b. Adaptive engine — how it runs itself

### The loop
```
charter + WAO corpus + skill profile + weakness memos
        │
        ▼
  COACH (Claude) ──generates──► today's session (persona + scenario JSON)
        │                              │
        │                        voice session (engine per §3)
        │                              │
        ▼                              ▼
  weekly plan ◄──updates──  JUDGE (Claude): scores + weakness memos
                                       │
                                       ▼
                          skill profile update (EWMA per skill)
```

### Inputs the Coach conditions on (no manual work)
1. **Training charter** — `data/trainer/charter.json`, written ONCE (~20 lines):
   goals, track weights, session length, red lines (e.g. "never train manipulative
   tactics"), tone preferences. This is the only manual artifact in the system.
2. **WAO corpus (already in the repo)** — service pages, the AI-funnel pitch, pricing
   logic, `scripts/onboarding-personas/` (real vertical personas: niches, fears, FAQs,
   objections). The Coach mines these so T1 personas are *actual WAO prospect types*,
   not generic buyers — practicing on the same personas the funnel targets.
3. **Skill profile** — `data/trainer/profile.json`: per-skill mastery 0–100, updated
   after each session as `mastery = 0.7·old + 0.3·(10·score)` (EWMA — recent
   performance dominates, old wins decay). ~10 skills: framing, brevity, listening
   ratio, emotion labeling, question quality, objection handling, boundary setting,
   storytelling, pace/fillers, closing.
4. **Weakness memos** — `data/trainer/memos.jsonl`: the Judge doesn't only score; it
   extracts recurring *patterns* as one-line memos with evidence quotes
   ("caves within 2 turns on price pushback", "talk ratio 71% in discovery",
   "answers before labeling the emotion"). Memos carry a live/resolved status —
   resolved when the pattern stops appearing for 3 consecutive relevant sessions.

### Scheduling policy (replaces the fixed 12-week plan)
- The 12-week curriculum in §6 is demoted to the Coach's **prior** — the starting
  syllabus when the profile is empty. From session ~5 onward the plan is emergent.
- **Next-session selection:** target the lowest-mastery skill that has a live memo;
  difficulty calibrated for ~70–80% expected success (desirable difficulty — hard
  enough to stretch, not demoralize). Passing streak of 2 at a level → level up.
- **Interleaving:** tracks rotate by charter weights; a skill trained in T1 gets a
  transfer rep in T3 within the week (e.g. objection handling → saying no to a friend).
- **Drill injection:** if a memo names a micro-habit (fillers, interrupting), the Coach
  prepends a 2-minute isolated drill before the main scenario.
- **Weekly cycle (automated, cron or on-first-open):** Coach regenerates the week plan,
  writes a short progress report (trend per skill, memos opened/closed), and retires
  stale scenarios. Zero clicks beyond "start today's session."

### Generated-content QA (automated Noa gate)
Generated Hebrew persona prompts and first messages pass an automated language-qa
step — a Noa-charter-prompted Claude call that checks native fluency, register, and
typography before the session starts. Fails regenerate once, then flag. No human gate.

### Real-call ingestion (M6, the end-game)
Upload real sales/networking call recordings (or WhatsApp voice notes) →
transcribe → the SAME Judge scores them against the same rubric → they update the
same profile and memos. Training scenarios then rehearse *actual* failure moments
from real WAO prospect calls — the tightest possible loop between practice and the
funnel's live conversations. (Consent/recording law check before recording clients —
one-party-consent applies in Israel when you're a party to the call, but keep
recordings local and gitignored.)

## 4. Architecture

- **UI:** `src/app/(app)/trainer/` — staff-gated (same auth pattern as the
  live-readiness admin UI). Pages: dashboard (progress + weekly plan), scenario
  library, live session room (mobile-usable), debrief/history.
- **Voice:** provider-abstracted per §3. ElevenLabs path: client SDK
  `@elevenlabs/react` (WebRTC); `POST /api/trainer/session` mints a signed
  conversation token server-side (API key never reaches the client; key already in
  `.env.local`). Transcript pulled server-side post-call via the conversation-history
  API. Gemini Live path: server-relayed WebSocket, transcript captured in-stream.
- **Judge:** `POST /api/trainer/debrief` → Claude (`claude-sonnet-5`) with the
  scenario rubric → structured JSON scores + feedback (feedback prose in English per
  house rule; quoted utterances stay Hebrew).
- **Coach & Judge:** `POST /api/trainer/next` — Coach generates today's session
  (persona + scenario JSON, cached); `POST /api/trainer/debrief` — Judge scores,
  emits memos, updates profile. Both are Claude calls (`claude-sonnet-5`), pennies
  per session next to voice-minute cost.
- **Data:** flat JSON, consistent with existing patterns — all generated, all
  gitignored except the charter:
  - `data/trainer/charter.json` — the one manual file (goals, track weights, red lines)
  - `data/trainer/generated/*.json` — Coach-generated personas + scenarios (cache)
  - `data/trainer/sessions/*.jsonl` — transcripts + scores
  - `data/trainer/profile.json` — skill mastery (EWMA)
  - `data/trainer/memos.jsonl` — weakness memos (live/resolved)

## 5. Data model

```ts
interface Persona {
  id: string;              // "danny-skeptical-plumber"
  name: string;            // Hebrew display name
  voiceId: string;         // provider voice id (Hebrew-capable)
  archetype: 'skeptic' | 'rambler' | 'aggressive' | 'anxious' | 'analytical'
           | 'friendly-flake' | 'price-hunter' | 'silent';
  systemPrompt: string;    // Hebrew role-play prompt: who they are, mood, hidden agenda
  hiddenObjective: string; // what actually convinces/moves them (judge uses this)
}

interface Scenario {
  id: string;
  title: string;
  week: number;            // position in the curriculum
  level: 1 | 2 | 3;        // difficulty variants of the same scenario
  personaId: string;
  situation: string;       // context shown to Eitan before starting
  firstMessage: string;    // agent's Hebrew opening line
  goal: string;            // success condition
  timeCapMin: number;
  rubric: RubricItem[];    // { skill, weight, description }
  drillsOnFail: string[];
}

interface SessionResult {
  scenarioId: string; level: number; startedAt: string;
  transcript: { role: 'user' | 'agent'; text: string; t: number }[];
  scores: Record<string, number>;   // per rubric skill, 0–10
  overall: number; passed: boolean; // pass ≥ 7 → unlock next level
  feedback: string; drills: string[];
}
```

**Levels:** L1 — cooperative persona, generous pacing. L2 — realistic resistance,
one hidden objection. L3 — hostile/chaotic, interruptions, emotional bait, agent
instructed to *not* be convinced by weak arguments. Passing L2 unlocks the next week;
L3 is mastery/replay.

## 6. Seed curriculum — 12 weeks (the Coach's prior, not a fixed plan)

This map seeds the Coach when the skill profile is empty; from ~session 5 the
scheduler in §3b takes over and the plan becomes emergent. Each week = 1 generated
micro-brief (~5 min read) + 3–4 voice scenarios at rising levels.

**Phase A — Foundations (W1–3): sound like someone worth listening to**
- W1 · First impressions & framing — open a cold call in 20 seconds; personas: busy
  store owner, distracted contractor. *(RISE 1, 3)*
- W2 · Voice, pace & silence — kill fillers, use pauses; drill: answer hard questions
  with a 2-second beat first. *(RISE 2)*
- W3 · Storytelling & analogy — explain SEO/PPC to a layman via analogy (WAO voice DNA);
  persona asks "מה זה בכלל?" repeatedly. *(RISE 5)*

**Phase B — Reading & regulating (W4–6): the EQ core**
- W4 · Deep listening & labeling — reflect the emotion before answering; judge scores
  listen/talk ratio and label accuracy. *(RISE 7, 13)*
- W5 · Empathy under fire — angry client whose campaign "wasted money"; validate
  without capitulating. *(RISE 9, 12)*
- W6 · Self-regulation & interruptions — persona interrupts and derails; recover
  smoothly, redirect without irritation. *(RISE 11)*

**Phase C — Influence (W7–9): move people**
- W7 · Asking questions that sell — discovery call; score: % of turns that are
  questions, quality of follow-ups.
- W8 · Objection handling — "יקר לי", "אחשוב על זה", "יש לי כבר מישהו"; L3 stacks
  three objections.
- W9 · Saying no & boundaries — decline scope creep and a discount demand while
  keeping the relationship warm. *(RISE 8, 10)*

**Phase D — WAO game-film (W10–12): the real thing**
- W10 · Full discovery call — end-to-end with a realistic vertical persona (reuse
  onboarding-personas data for realism).
- W11 · The pricing conversation — present retainer, hold price, close or schedule.
- W12 · Difficult conversations — churn-risk client, delivering bad results honestly,
  asking for a referral. *(RISE 9, 12)*

**Long-term (post-W12):** rotation mode — daily random scenario at L3, new personas
added monthly, skill-radar tracks the 8 rubric skills over time; weakest skill gets
scheduled twice a week.

## 7. Build order (for Eitan-Dev)

1. **M1 — Voice room + engine bake-off:** ElevenLabs Agents end-to-end with one
   hardcoded persona; parallel Gemini Live Hebrew probe script. Decide the engine.
2. **M2 — Coach generator:** charter file, `POST /api/trainer/next` generating
   persona + scenario from charter + WAO corpus (incl. onboarding-personas), with the
   automated Noa QA step. Session runs from generated JSON — no authored content.
3. **M3 — Judge & adaptive loop:** debrief route (scores + weakness memos), profile
   EWMA updates, next-session scheduling policy, dashboard with skill radar + memos.
4. **M4 — Weekly automation:** cron/on-open weekly plan regeneration + progress
   report; drill injection; track interleaving.
5. **M5 — Polish:** streaks, rotation mode, mobile session room refinement.
6. **M6 — Real-call ingestion:** upload → transcribe → same Judge → same profile.

**Gates:** the automated Noa QA step covers generated Hebrew (spot-audit by real
language-qa monthly). Anything built → verifier (Roni) runtime-confirms a full
generated session + stored debrief + profile update before "done."
